## 修复 ESP32-S3 播放音频跳跃/卡顿

根因（三处，按影响排序）：

1. **TTS 队列满时丢帧**（`Tts/TtsMatchaIcefall.cs`）
   Matcha steps-3 推理约 20~40x 实时，长回复几秒就生成完；旧 `EnqueueFrame` 在
   队列满（200 帧 = 4s）时 "丢最旧"，等于成段扔掉已合成语音 → 直接听成跳字。
   改为：阻塞式反压合成线程（合成线程上下文阻塞安全），队列上限提到 400 帧。
2. **句子之间串行等待**（`Llm.cs`）
   旧 `TtsPlayLoop` 是「生成一句 → 等播完 → 再生成下一句」，句间空档 = 一次完整推理，
   ESP32 抖动缓冲被抽干 → 重新预缓冲 → 每句顿一下。
   改为：删除该线程，`EnqueueTts` 直接调 `tts.Enqueue`；TTS 内部新增 `textQueue`
   + `SynthLoop` 串行连续推理，PCM 持续追加到同一 `sendQueue`，句间不清队列、不补零。
   打断改用 `generation` 自增代号，回调检测代号变化返回 0。
3. **缓冲水位过低 + 20ms 小包**（`client/client.ino`、`TtsMatchaIcefall.cs`）
   - 抖动缓冲 24 帧(480ms) → 64 帧(1280ms, 40KB 静态)，I2S TX DMA 8→12 帧(240ms)
   - 引入双水位：冷启动 10 帧(200ms)，中途欠载后 `RESUME_FRAMES=3`(60ms) 快速续播
     （此时 DMA 里仍有存货，高水位干等反而放空 DMA）
   - 服务端每包聚合 3 帧 = 60ms，包数降到 1/3，规避 Nagle 造成的不规律突发
   - 发送节拍从 `Sleep` 累加改为 `Stopwatch` + "应发帧数"，无累积漂移；
     发送线程 `ThreadPriority.AboveNormal`
   - 每轮灌 DMA 上限 4 帧 → 16 帧；新增 `underruns` 诊断计数

编译验证：`dotnet build -t:Compile` 0 错误（完整 build 会因 server.exe 被占用而
MSB3027 文件锁失败，与代码无关）。
